# IH-Challenge dataset audit

The first full streaming audit of the working Hugging Face bucket copy completed successfully on 2026-09-05.

## Totals

- Total rows: **27,570**
- `single-constraint.jsonl`: **1,900**
- `multi-constraint.jsonl`: **4,832**
- `input-conditioned.jsonl`: **19,038**
- `anti-overrefusal.jsonl`: **1,800**

## Authority distribution

Across the full dataset:

- Attacker role: **18,459 user**, **9,111 developer**
- Privileged role: **18,736 system**, **8,834 developer**

This imbalance matters for evaluation design. A naive random sample would mostly estimate system-vs-user behavior and would underrepresent developer-level attackers and developer-level privileged instructions.

## Task-family distribution

The dataset is also strongly imbalanced by family:

- `blue_team_auto`: **19,038**
- `composite`: **4,832**
- most hand-constructed single-rule task types: **200 each** across single-constraint + anti-overrefusal
- `do_not_swear`: **100** and appears only in single-constraint

Therefore the first pilot should be **stratified by file / task family and authority pair**, rather than sampled uniformly from all 27,570 rows.

## Pilot implication

The initial `25 items per file` plan is deliberately balanced across the four top-level files. Within each file, the next sampling layer should preserve coverage of:

1. system -> user conflicts;
2. system -> developer conflicts;
3. developer -> user conflicts;
4. task subtype where applicable.

For the large input-conditioned split, random sampling alone is acceptable only after verifying that `blue_team_auto` contains meaningful internal substructure in metadata or prompt templates.

## Reproducibility

The audit is generated by `scripts/audit_dataset.py` and `.github/workflows/dataset-audit.yml`. The versioned machine-readable snapshot is stored at `reports/ih_challenge_audit.json`.
